Local x402 payment guard

Run the normal flow, or act as a red team member and alter one field in the HTTP 402 offer. The deterministic payer agent checks its own policy before it lets the x402 SDK call the signer.

Mock mode: the payer guard is real control flow, but the wallet is a mock signer that returns a placeholder. No private key or funds are used.
1 · Parse offerclient.py decodes the HTTP 402 requirements.
2 · Payer policyAgent checks the offer against its own trusted limits and allowlists.
3 · Sign only after ALLOWOnly then does the x402 SDK call the mock signer.
4 · RetryA denied offer never sends a payment retry.
5 · Optional server validationThe resource server checks a retry only if the payer sent one.

Red-team injection point: an attack may alter the parsed offer after step 1 and before step 2. It cannot change the payer's trusted policy.

Examples: amount 20000; recipient or asset a different 0x address; network eip155:8453.
